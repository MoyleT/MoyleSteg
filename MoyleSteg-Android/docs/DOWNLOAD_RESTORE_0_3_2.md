# Android 0.3.2-alpha · 恢复后保存与打开

版本：`0.3.2-alpha`，`versionCode 7`。本说明描述实现行为与验收边界；实际测试和构建结果见
[0.3.2 验证报告](../verification/TEST_REPORT_0_3_2.md)，设备待验收项目见 [设备清单](DEVICE_ACCEPTANCE.md)。
本版没有手机或模拟器验收记录，主机测试不能替代真实系统文件管理器、权限弹窗或查看应用的验证。

## 恢复流程

PNG、GIF 和独立 SAES 均按以下顺序恢复：

1. 捕获输入，使用口令或密钥完成完整认证，生成应用私有明文成品及其摘要。
2. 根据认证后的原文件名和最多 4 KiB 文件头推断 MIME，检查私有成品仍与已认证的长度和 SHA-256 相符。
3. 在主共享存储的公共 `Download/` 根目录创建新文件，分块写入，再完整回读核对长度与 SHA-256。
4. 完成保存提交后，结果卡显示实际保存名称和位置，提供“打开文件”和“另存一份”。

保存不要求先选择文件夹。写入只针对本次新建的文件，不用原文件名重新打开已有文件覆盖。
例如重复恢复 `report.pdf` 可能得到 `report (1).pdf`；Android 系统也可能调整名称，界面以实际返回的名称为准。
保存完成不会自动弹出查看应用或安装程序。只读“验证文件”不向共享存储写出明文。

## 保存失败、取消与清理

| 状态 | 结果与可继续操作 |
|---|---|
| 凭据错误、认证失败或认证前取消 | 不创建公共恢复文件；未完成的私有输出清理，不显示可打开的成功结果 |
| 已认证，但保存失败或保存提交前安全取消 | 显示“已恢复，尚未保存”；保留当前私有成品，允许重试 Download 保存或选择其他位置，无需重新解密 |
| Android 8／9 未获得保存权限 | 当前认证成品保留；可授权后继续、再次重试，或通过系统选择器保存到其他位置 |
| 保存完成后才收到取消请求 | 已完成的公开文件保留，不把成功提交改报为未完成 |
| 清空结果或切换到会清理当前结果的操作 | 清理私有成品；已经成功保存的 Download 文件或 SAF 副本保留 |
| 进程结束、崩溃或应用重启 | 不保证保留待重试任务；下次进程启动清理残留私有成品，公共成品仍保留 |

失败清理只针对本次输出，并尽力避免触碰已有文件。系统拒绝删除、输出被替换或进程突然终止时，
不能保证不存在残留的 pending 条目或部分文件；遇到清理失败提示，应检查保存目录后再重试。
“安全取消”是协作式取消，密码学调用可能需要运行到安全点才能响应。

## Android 版本差异

| 系统 | 保存方式 | 授权与可见性 |
|---|---|---|
| Android 10 及以上／API 29+ | 新建应用自己的 `MediaStore.Downloads` 条目，`RELATIVE_PATH` 为 `Download/`；写入、同步、回读验证后把 `IS_PENDING` 从 1 改为 0 | 不申请存储权限；pending 阶段由系统限制其他应用访问，发布后成为公共下载文件 |
| Android 8／9／API 26–28 | 在公共 Download 中排他创建新文件；同名时递增后缀，写入后完整回读；用只读 FileProvider 提供打开 URI | 请求 `WRITE_EXTERNAL_STORAGE`，声明限制到 API 28；没有 pending 隔离，其他有权限的应用可能看到尚未完整写入或校验的文件 |

应用始终在完整回读验证后才报告保存成功。旧 Android 的共享目录不是私有临时区，也不能提供对恶意并发修改者的文件系统快照保证。
输入文件、隐藏后的 PNG／GIF、独立加密后的 SAES、密钥导出和“另存一份”继续使用 SAF 系统文件选择器。
SAF 提供方的空文档、回读、删除和权限差异仍适用；详情见 [README 的导出边界](../README.md#隐私与导出边界)。

API 29+ 的应用自有 Download 文件免存储权限，依据 Android 的
[共享存储说明](https://developer.android.com/training/data-storage/shared/media#storage-permissions)；pending 访问约束见
[`IS_PENDING` 文档](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns#IS_PENDING)。

## 打开方式与 MIME

“打开文件”只在用户明确点击后启动系统 chooser。目标为 `ACTION_VIEW`，使用一个 `content` URI、
`ClipData` 和临时 `FLAG_GRANT_READ_URI_PERMISSION`，不授予写权限，也不把文件路径作为 `file://` URI 发送。
系统让用户选择查看应用；完成保存本身不会启动查看应用。

类型识别最多读取 4 KiB，随后关闭文件，不为识别格式读入整个 1 GiB 载荷。
支持常见 PNG、JPEG、GIF、PDF、ZIP、MP4、文本等文件头，并结合原文件名的扩展名。
DOCX、XLSX、PPTX 等 ZIP 容器保留具体文档 MIME；HTML 和 APK 使用相应类型，不把 APK 伪装为普通 ZIP。
这只是应用选择提示，不是文件格式或内容安全验证。

无法识别的类型以 `application/octet-stream` 保存；用户点击打开时可用 `*/*` 让系统提供其他应用选择。
没有合适的应用、用户取消 chooser 或读取被系统拒绝时，保存文件保留。界面或系统提供提示，用户仍可从保存位置或文件管理器找到文件，
也可在当前结果中另存一份。chooser 已启动不表示某个应用已经成功读取文件。
应用不执行恢复文件，也不发出自动安装请求；APK 的后续处理由用户选择和系统交互决定。

打开流程直接启动 Intent 并处理 `ActivityNotFoundException`／权限失败，不预先枚举安装应用，
无需为此增加包可见性查询声明。依据 [Android 文件打开建议](https://developer.android.com/training/package-visibility/use-cases#open-a-file)。

## 明文保留范围

Download 中是已经解密的原文件。清空结果仅清理应用的私有成品和界面状态，卸载应用也不会由本应用删除公共文件。
用户应在系统文件管理器中管理这些副本；同样，已经通过 SAF 另存的副本不会因清空结果被撤回。

应用本身不申请联网权限。系统文档提供方或用户选择的查看应用有各自的权限和处理方式，可能联网、同步或另存文件。
私有目录禁用备份，但普通删除、JVM 内存回收和闪存均不提供物理安全擦除保证。
