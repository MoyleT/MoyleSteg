# Android 0.4.1-alpha · 多文件可靠性修复

本版 `versionCode 9` 保留 0.4.0 的多文件流程、三主题及 PNG／GIF／SAES v1 格式。
更新集中在临时空间、文件选择取消和导航期间的成果保护，不增加新的隐写格式。

## 分阶段检查临时磁盘

多文件任务在不同阶段会持有源捕获副本、ZIP、加密容器或待保存成员。只限制每个
输入文件的大小，不能代表后续阶段仍有足够临时空间。

现在按阶段保守估算尚需新增的私有空间，并保留 **32 MiB（33,554,432 字节）余量**。
创建 ZIP 的估算包含压缩可能带来的增长和成员目录开销；捕获、打包、后续封装与
成员恢复分别检查各自还需写入的空间。已经存在的副本已经减少可用空间，不应重复
计入尚需写入的字节。写入过程中继续检查边界，空间不足与磁盘配额错误给出明确提示。

ZIP 写入完成并独立回读校验后，先释放各源文件的捕获副本，再继续加密。认证后的
恢复 ZIP 则保留到用户完成选择保存或主动丢弃，以支持重试；每项恢复临时文件用完后
释放。取消或失败不会删除已经提交到 Download／SAF 的文件。

这些数值是准入与过程检查，**不是磁盘预留，也不是精确预测压缩率或峰值占用**。
其他应用仍可能在检查后占用空间，提供方也可能有独立配额；后续写入错误仍须处理。
保守估算可能提前拒绝实际压缩后能够放下的任务。内存预算、图片像素上限、源文件
总量与 ZIP 大小限制继续独立生效，不能用可用磁盘空间替代它们。

## 取消真正关联到当前文件选择

每个文件选择请求拥有独立的协程任务、版本标识与 CancellationSignal。用户取消、
更换选择或实际切换功能时，会取消旧请求；文件元数据查询和打开读取使用支持取消的
提供方接口，并尝试关闭已经打开的本次读取句柄。读取检查点继续检查取消状态。

旧请求即使较晚返回，也不能替换新文件、覆盖新状态或解除新请求的等待标识。
取消不应当被吞成“无法读取预览”，随后继续使用旧数据。

这仍是协作式取消。支持 CancellationSignal 的提供方可以更早响应；忽略取消、
卡在系统调用或自身网络访问中的提供方不保证立即退出。应用没有强制终止外部
提供方进程的能力，也不声称瞬间中断所有读取或密码学计算。

## 设置与当前成果分开管理

- 进入设置再返回当前功能，保留文件列表、载体／密钥选择和认证结果；预算与外观
  修改不会删除尚未保存的私有成果。手动预算变更会撤销本次确认，开始任务前仍重新检查。
- 当前子功能会保留，例如“只读验证”和“生成密钥”不会在设置返回后回退到默认功能。
  重复点击当前页或当前子功能不重置状态；设置页返回键回到当前功能。
- 真正切换功能或清空结果时，如果尚有未保存的成品、密钥或恢复成员，先显示丢弃确认。
  取消确认保留当前状态，确认后才删除私有成果并切换。确认与当时的结果绑定，过期确认
  不得删除另一份新结果。
- 已保存单文件、全部成员已保存或完整 ZIP 已成功导出的结果已有公开副本，正常离开
  会释放私有副本。公共 Download／SAF 文件始终保留，不由导航或清空结果删除。

表单口令继续按既有隐私策略清理，不写入设置。保留当前结果不代表后台续跑或进程
重启恢复；清理也不是 SSD、系统缓存或内存的物理安全擦除承诺。
