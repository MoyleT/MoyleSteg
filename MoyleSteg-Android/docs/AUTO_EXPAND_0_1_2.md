# 0.1.2-alpha 自动扩容说明

隐藏页默认开启“容量不足时自动扩容”。选择 PNG 载体和秘密文件后，先检查实际容量：原载体够用时，保持原来的宽高；不够用时，在写入隐写数据之前放大载体，再完成加密、嵌入及保存后验证。关闭该开关后，容量不足会明确拒绝，不生成成品。

扩容使用同一个缩放比例计算宽高，再分别向上取整为整数像素，因此极小尺寸下可能存在取整带来的轻微比例差异。像素通过双线性插值生成。需要扩容时，以密文占有效容量不超过 90% 为目标；原图本来就够用时，即使占用超过 90%，也不会仅为达到这个目标而放大。

扩容仅处理任务内捕获的载体数据，成品通过系统文件选择器另存；不会改写原载体。放大增加可容纳数据的像素数量，不会增加原照片的细节或画质。应把成品 PNG 作为原文件发送，避免社交软件的图片压缩、缩放或重新编码。

实际容量预检会读取秘密文件并执行真实压缩，计算包含格式开销的密文长度，并显示原载体尺寸、计划输出尺寸、是否扩容、有效容量、实际所需字节、占用率及估算的 PNG 工作内存。它使用的计划与隐藏流程一致，但不会提前保留内存或存储空间，也不会锁定文档提供方的文件。正式执行仍会重新读取并检查输入；源文件变化或设备资源变化时，结果可能不同。

默认资源限制保持如下：

| 预算 | 默认上限 |
| --- | --- |
| 原始秘密文件 | 4 MiB |
| PNG 像素 | 12,000,000 像素 |
| 完整容器文件 | 64 MiB |
| PNG 工作缓冲估算 | 96 MiB |
| PNG 单行缓冲 | 4 MiB |

MiB 按 1,048,576 字节计算。PNG 工作缓冲估算不等于整个应用的峰值内存，也不保证设备一定能够处理；实际可用堆空间等条件仍可能使任务拒绝。扩容计划超出像素、行缓冲或工作内存预算时，不会继续无限放大。

如果 PNG 扩容受到这些预算限制，可使用独立 SAES 加密来避免图片容量和像素缓冲成本。SAES 同样受原始文件及容器上限约束，不会绕过 4 MiB 的载荷限制。

自动扩容只适用于创建新的隐写 PNG。恢复和只读验证均不重采样现有容器；对已有隐写图片进行缩放、裁剪、插值或重新保存，可能破坏其隐藏数据。遇到恢复资源超限，应保留原文件，在资源与预算足够的环境中恢复。

核心 API 的 `preflight(..., autoExpand = false)` 和 `hide(..., autoExpand = false)` 默认保持原有行为；调用方需要显式传入 `autoExpand = true` 才会规划或执行扩容。Android 隐藏页的开关默认开启，预检与实际隐藏均传递同一个设置。更改开关会清除旧结果；任务执行中忽略开关修改，避免当前界面与正在运行的任务混淆。

这项功能改变的是嵌入前的载体尺寸，不改变 PNG 隐写协议、SAES 容器、密钥文件或认证载荷格式。原有恢复端仍可按相同协议读取成品，但须支持成品的 PNG 类型，并具有足够的处理预算。

本文描述功能行为与边界，不作为测试通过、APK 构建成功或手机实机验收的证明。测试环境、实际执行范围和结果应以对应版本的测试报告为准。
