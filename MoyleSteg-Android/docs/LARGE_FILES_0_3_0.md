# 0.3.0-alpha：大文件、内存预算与文件尺寸

## 如何选择

几百 MB 到 1 GiB 的原文件使用“工具 → 独立 SAES 加密”。恢复页自动识别 PNG、GIF 和 SAES 的文件签名，不靠后缀决定解析器。SAES 的加密、恢复、只读验证和导出均使用分块文件处理。

PNG 和 GIF 的原文件上限为 32 MiB、完整容器上限为 128 MiB。图片核心仍有完整图像／载荷数组；即使文件能压缩得很小，也要符合解压后的预算。不要把 1 GiB SAES 支持理解为可以隐藏 1 GiB 到单张 PNG。GIF 仍保留原动画并附加标准应用扩展，不改变动画像素。

## 自动与手动内存

默认读取 Runtime 的堆上限和已用堆，以及 ActivityManager.MemoryInfo 的系统可用内存与低内存状态。读取这些信息无需新增权限，也不会读取其他应用的文件或内存内容。

自动预算同时受应用堆、当前可用堆、系统可用内存的保守比例约束。手动预算范围为 32 MiB 到当前计算的最大值（绝对最高 512 MiB）；口令派生任务至少需要 64 MiB。系统低内存或不足以保留余量时拒绝开始，不会静默提高用户输入的值。

“手动预算”是操作准入限制，不是向 Android 申请指定大小的内存，更不是占用或锁定这部分 RAM。程序不能把手机总运行内存全部分配给自己。开始任务时会重新观测；图片解码、密文处理和解压之前继续检查实际堆余量。其他应用及同进程线程仍可能在观测后使用资源。

手动模式需要确认本次预算；更换输入、操作、凭据模式或预算，以及任务结束后撤销确认。自动模式不要求额外确认。

## 磁盘成本与认证

SAES 大文件处理把内存成本转换为多次磁盘读写。系统文件选择器输入先捕获到私有目录，再重新打开核对完整摘要；不能重新读取的提供方需要先保存一份稳定的本机文件。

加密期间可能同时存在输入捕获、原始快照、压缩候选、加密成品与回读验证副本。对于不可压缩的 1 GiB 输入，应准备数 GiB 的应用私有存储可用空间，另为最终导出准备空间。程序按各阶段实际需求检查并保留 32 MiB 余量；这不是磁盘预留，其他程序仍可能占用空间。写入错误会拒绝成功结果并尝试清理本次临时文件。

v1 SAES 的头部、PAY1、随机 salt／nonce、scrypt、HKDF 与 GCM 不变。流式解码先完整认证私有容器副本，丢弃该遍产生的明文；然后第二遍解析、解压、计算原文摘要，并再次核验认证和容器摘要一致。只读验证不生成明文文件。恢复输出只在完整认证、长度、解压结束状态及 SHA-256 全部通过后交付给界面。

加密输出在私有目录保存后独立回读验证。应用在展示可保存结果之前也会回读私有恢复文件的摘要。导出仍要求新的空目标，保护输入和密钥 URI，并在关闭写出流后回读核对长度与摘要。SAF 提供方没有统一的原子禁止替换接口，空目标检查不能承诺抵御其他写者同时修改目标。取消在安全检查点响应，可能需要等待一次同步调用完成。不承诺进程被系统终止后的续跑或物理安全擦除；下次启动清理残留私有工作目录。

## 相册显示 0×0

文件选择区最多读取 54 字节，显示签名识别格式、PNG IHDR／GIF 文件头中的尺寸，并明确标为“尚未验证”。这不会解码图片，也不能证明格式或载荷完整。

相册中的尺寸可能来自系统索引。能正常恢复的小 PNG 在相册显示 0×0，不能简单归因于大图资源超限，也不能凭截图判定发生了 JPEG 重编码。需要实际接收文件才能区分后缀／格式标识、索引和解码问题。当前版本提供诊断信息，不宣称已经修复微信或相册索引。

不要通过压缩、裁剪、截图、旋转或重新保存已有隐写图片来修正相册显示；这些操作可能损坏载荷。跨端传输优先使用文件发送，比较完整容器 SHA-256 可以判断传输前后字节是否一致。恢复成功只证明经过认证的隐藏内容正确，不代表所有外层元数据都未变化。

## 设备验证边界

真实执行记录在版本测试报告中。JVM 主机小堆测试与 Robolectric 流程测试不能替代 Android 真机的存储提供方、前后台生命周期、画面和性能验收。此版保持现有前台操作方式，没有增加后台续跑服务。
