# GIF 动画载体 · Windows 1.5.0 / Android 0.2.0-alpha

两端可选 GIF 动图作为载体，输出仍为 GIF。PNG 像素隐写、独立 SAES、口令和密钥文件继续保留原格式。

## 用户行为

选择原始 GIF 和秘密文件，先预检，再设置口令或 `.stegkey`，最后保存为新的 `.gif`。GIF 的画面、调色板、透明设置、帧间隔、帧处置方式、循环设置和原始图像数据均保留。GIF 不做像素扩容；预检以实际压缩后的密文和完整成品字节预算计算，显示帧数、画布尺寸及预计输出大小。桌面预览显示首帧，不表示仅保存了首帧。

提取与只读验证自动识别 GIF 签名。两端都升级后，可互相恢复 GIF 中的原文件；旧版本仍可播放这些 GIF，但不能通过旧的 PNG/SAES 恢复入口识别新 GIF 容器。PNG/SAES 的旧格式互通不受影响。

GIF 使用**标准应用扩展块承载加密文件**，并非 PNG 的 RGB 最低位像素隐写。文件分析工具能够识别扩展块的存在，保密依赖口令/密钥与 AES-GCM。重编码、优化、转视频或聊天软件重新处理 GIF 可能删除扩展；请按原始文件发送。AES-GCM 认证隐藏文件及其内部元数据，**不认证外层动画**。完整 GIF 的 SHA-256 标识本次读取的整个容器，与原文件 SHA-256 含义不同。原 GIF 自带的注释和扩展也会保留。

## 共享格式

依据 [CompuServe GIF89a 规范（W3C 托管）](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)，在结构解析得到的 Trailer `3B` 前加入一个应用扩展：

```text
21 FF 0B
MOYLESTG       8 字节 Application Identifier
001            3 字节版本标识
[长度 1..255][数据] ...
00
3B             原 Trailer
```

子块拼接内容为现有的完整 SAES 字节序列，即 54 字节的 v1 头部，加头部声明长度的 AES-256-GCM 密文和认证标签。`001` 是协议版本标识，不是密码学认证。写入端每块最多 255 字节，恢复端接受任意合法的 1..255 字节分块。

原 GIF 长度为 C、完整 SAES 长度为 N 时，成品精确大小为：

```text
C + N + ceil(N / 255) + 15
```

GIF87a 标头会升级到 GIF89a；其余原始块按字节保留，不用图片编码器重存。拒绝已含任意 `MOYLESTG` 版本扩展的载体，避免隐式替换旧载荷；恢复拒绝重复或未知版本扩展、声明长度不匹配及截断数据。不会搜索最后一个 `3B` 或在压缩数据里搜索字符串来定位载荷。

## 输入与资源边界

两端顺序验证 GIF 块、颜色表、帧矩形、图形控制及 LZW 码流。LZW 验证使用固定 4096 项字典检查码值、像素数和颜色索引；允许初始颜色字面码和合法字典增长，必须有结束码。输入至少包含一帧图像，帧须位于逻辑画布内；缺少颜色表、未定义的处置方式、悬空控制块、结束标记后的尾部等会明确拒绝。合法的未知应用扩展/注释按结构保留。

默认最多 500 帧，逻辑画布像素数 × 图像帧数最多 100,000,000。逐帧与画布尺寸也受各端像素预算限制。Windows 默认 2500 万像素、256 MiB 载荷；桌面服务显式采用 512 MiB 容器预算，CLI/API 的 GIF 容器默认预算为 64 MiB。Android 默认 1200 万像素、4 MiB 载荷和 64 MiB 容器。两端预算不同，因此格式兼容不等于较大的桌面文件一定能在手机恢复。

Windows 会在结构与动画预算准入后用 Pillow 逐帧验证；Kotlin 核心无需为 GIF 解码分配整幅像素数组。移动端输出前还检查当前可用堆。检查不是资源预留，也不承诺任意设备处理速度。恢复原文件时不要用缩放或重存 GIF 绕过预算。

捕获输入时执行有界读取和内容一致性核对；认证和摘要基于本次捕获的相同数据，不能据此声称操作系统快照。保存沿用各端既有的私有临时成品、保存后认证和安全导出流程。扫描、帧检查、复制和提交之间响应协作式取消。
