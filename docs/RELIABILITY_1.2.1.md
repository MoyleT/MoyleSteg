# 1.2.1 可靠性修复与验证说明（历史记录）

本文记录 **1.2.1 的历史改动和验证结果**，其中测试数量、耗时、EXE 自检及跨版本实验均不作为 1.2.2 的验证证据。当前版本的只读验证修复、验证范围和限制见 `VERIFICATION_1.2.2.md`；当前打包规则见 `RELEASE.md`。下文的“本轮”“本版本”和“当前”均指历史 1.2.1 验证时点。

1.2.1 保持容器格式 v1、密钥格式 v1 及既有加密协议不变。本次更新集中于组合生成密钥、输入读取一致性、长文件名及开发测试入口。本文只使用合成数据描述验证范围；原始本机日志、诊断 JSON 和截图不随公开工程包分发。

## 修复范围

| 场景 | 1.2.1 的处理 |
| --- | --- |
| 隐藏或加密时同时创建新密钥 | 组合 CLI 禁止 `--force-key`，即使指定的是尚不存在的新路径也拒绝；生成密钥始终使用 `force=False`。独立 `keygen --force` 仍可在明确授权后替换密钥。 |
| 输入文件在读取期间改变 | 隐藏、加密、容量预检的载荷读取及 SAES 密文读取使用共同的 `_read_bounded` 检查；发现可观察的文件状态、长度或内容变化时拒绝继续或发布结果。 |
| 合法长文件名导致临时输出创建失败 | PNG 保存及 `_atomic_write` 的同目录临时文件统一使用短前缀，不再把完整目标文件名重复添加到随机临时名中。仍受操作系统路径和文件系统本身的长度限制。 |
| 开发测试入口与桌面依赖不一致 | 开发测试入口统一使用项目虚拟环境和所需桌面测试依赖；Qt 测试使用应用实际采用的 Fusion 样式。无显示运行与原生 Windows 界面验证分别记录。 |

组合任务创建新密钥后，如果后续操作失败或收到 `KeyboardInterrupt`，会保留已创建的新密钥，并在标准错误输出中给出其绝对路径和使用 `--key-file` 重试的提示。不会回滚两个文件，也不会因为失败而替换原有密钥或提交新的输出去覆盖旧输出。本机错误日志因此可能包含绝对路径，须继续留在公开包之外。

独立复核还复现了密钥权限设置期间取消导致漏报新密钥的时序。权限现在先在临时文件上设置，再提交密钥；该检查点取消时清理临时文件，不发布密钥。独立密钥工具仍保留显式替换功能，替换前应备份旧密钥。

输入检查使用无缓冲二进制句柄，在读取前、每段读取和最终回调之后比较句柄 `fstat` 与路径 `stat` 的设备/文件标识、大小及修改时间；POSIX 另比较状态变更时间。随后在同一句柄上回到原始偏移，逐块再次读取并比较内容。这增加一次读取 I/O，并提供可取消的 `check_input` 阶段。检查只检测可观察的变化，不提供严格文件快照，也不保证识别所有恶意并发修改。PNG 载体解码及短密钥头部读取不在此次一致性改动范围内。

Windows 扩展路径的合成复现中，249 字符的最终文件名可以合法创建，旧临时命名方式却因附加随机字符和后缀而失败；改用短前缀后，四条相关写入路径通过该复现。此结果不表示取消 Windows 或文件系统的路径长度限制。

默认资源预算仍为 **25,000,000 像素、256 MiB 原始文件**。内存估算不是峰值保证；PNG 和 SAES 处理仍使用内存，未增加流式大文件格式。

验证顺序与可重跑命令：

1. 检查差异并运行针对性复现。新增 `tests/test_reliability_121.py` 的 31 项回归包含原触发条件、普通成功控制、长文件名四条写入路径，以及独立复核新增的权限准备取消检查。旧版上可复现的混合内容与长临时名失败，在候选修复中均被阻止或正常保存；既有密钥字节与历史容器仍可使用。
2. 运行 `python -m pytest tests/test_reliability_121.py tests/test_core_safety.py tests/test_core_resources_progress.py -q`，83 项通过，包括独立 CLI 进程竞争同一输出、取消清理、资源与路径保护。随后运行最终完整入口 `.venv/Scripts/python.exe scripts/run_tests.py full -- -q --tb=short`，结果见上表。
3. 用 `python -m venv artifacts/core-env-1.2.1` 新建环境，仅安装 `requirements-dev.txt`，确认 `PySide6` 和 `pytestqt` 均不存在后，禁用第三方插件自动加载并执行 `python -m pytest --core -q --tb=short`。另用 `QT_QPA_PLATFORM=windows` 运行全部 GUI 模块。`tests/test_test_entry.py` 的 6 项回归覆盖核心原位运行、缺少 GUI 依赖的明确错误、真实 pytest 退出码和 Windows 批处理解析。
4. 执行 `.venv/Scripts/python.exe scripts/build_desktop.py`，干净构建成功，再运行 `dist/MoyleSteg/MoyleSteg.exe --self-test <运行目录之外的报告路径>`，17 项通过。实际自检报告与截图保留在本机，不纳入公开包。

## 官方接口依据

- [CPython 3.13 的 `tempfile.py`](https://github.com/python/cpython/blob/3.13/Lib/tempfile.py)：临时文件名由前缀、候选随机名称和后缀组合；缩短调用方提供的前缀可避免重复占用文件名长度。
- [Python `os.stat_result`](https://docs.python.org/3/library/os.html#os.stat_result)：说明文件标识、大小及时间戳字段的含义与平台差异；这些状态信息不是文件快照保证。
- [Python `open`](https://docs.python.org/3/library/functions.html#open)：二进制模式下的 `buffering=0` 关闭 Python 文件对象缓冲；这不意味着绕过操作系统缓存。
